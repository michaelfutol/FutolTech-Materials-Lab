# Native Structures report print direction

## Visual character

Printed reports should look like traditional engineering calculation sheets and drafting-room output, not presentation decks or social-media infographics.

- white paper
- black and grayscale linework
- Microsoft Sans Serif / Arial body text
- thin rules and table borders
- conventional dimension lines, extension lines, support symbols and load arrows
- no gradients, glow, dramatic color coding or decorative logo boxes
- use whitespace deliberately for readability and continuity

## Direct comparison figure

The report should include a black-line test schematic generated from the active inputs:

- selected support condition
- member span or column height
- force arrow and force value
- load position or eccentricity
- deflected or buckled-shape reference when useful
- simple cross-section sketches for Members A/B/C

The figure is explanatory and must use the same numerical test inputs as the solver.

## Public wording

Do not print internal development language such as "one touch", "last survivor", "overshoot" or other conversational implementation wording. Use engineering labels such as "Automatic comparison threshold search" and "Comparison load threshold".

## Pagination

Use safe margins before paper utilization. Do not compress a complete table, member group or engineering figure merely to remove blank space. Prefer clear page breaks and intact content blocks.
